# 通常問題画面の表示領域: 実装記録

2026-09-15。対象は画面08（CaptureGameScene）です。

## 実装した領域

ゲーム内座標390×844に対する比率です。境界線を常時表示する変更ではなく、描画と操作が使う範囲をコードで分けています。

| 領域 | 横位置・幅 | 縦位置 | 高さ | 画面高さ比 |
|---|---|---|---:|---:|
| モンスター・ゲージ | x28・幅334（85.6%） | 78〜244 | 166 | 19.7% |
| 数字入力用の問題・回答欄 | x16・幅358（91.8%） | 252〜456 | 204 | 24.2% |
| 数字キー | x24・幅342（87.7%） | 464〜744 | 280 | 33.2% |
| 判定 | x24・幅342（87.7%） | 760〜832 | 72 | 8.5% |

通常の数字キーは幅88・高さ64を維持しました。行間隔は82から72へ変更し、キー間に8の隙間を確保しています。小数入力の最下段は、従来どおり幅76の4ボタンです。

### 選択肢用

| 領域 | 縦位置 | 高さ | 画面高さ比 |
|---|---|---:|---:|
| 問題 | 252〜420 | 168 | 19.9% |
| 選択肢 | 432〜680 | 248 | 29.4% |
| 消去・確定 | 690〜746 | 56 | 6.6% |
| 判定 | 760〜832 | 72 | 8.5% |

選択肢は実際のフォントで測定し、指定された4列／2列／1列を出発点に、必要なら列数を減らします。全カードで文字サイズをそろえ、28〜22の範囲で調整します。短い数値が狭いカードで改行されるより、列数を減らすことを優先します。

4つの語「センチメートル／ミリメートル／ミリリットル／デシリットル」を測定した結果は、幅334・高さ53の1列4段、文字サイズ28でした。この測定はレイアウト処理の確認用で、長さ・かさの出題データや採点はまだ追加していません。

最小サイズでも全選択肢が収まらない入力は、例外として検出します。選択肢を黙って欠落させることはしません。将来の長い選択肢や件数変更は、開発用確認ページで検証してから追加する必要があります。

### 方眼用

従来からモンスター部分に重ねる方式だった方眼は、別の領域として維持しました。パネルはx26、y90、幅338、高さ354（画面高さ41.9%）、下端444。図の最大高さを170へ広げ、式と回答文をその下に置きます。数字キーの上端464まで20の余白があります。

## 主な変更

- `src/game/layoutConfig.ts`: 領域をまとめ、数字キーの行間・開始位置、問題の基準位置、判定の中心を領域から決めるよう整理。
- `src/game/ui/problem/CaptureProblemView.ts`: 問題を下へ移動し、時計・分数・ルートの上端とモンスターパネルを分離。筆算の□と回答欄、図形の辺ラベルと回答欄も調整。
- `src/game/ui/problem/choiceCardLayout.ts`: 選択肢の全文を測り、列数・共通文字サイズ・カード座標を決定。
- `src/game/scenes/capture/CaptureGameScene.ts`: 問題ごとに数字キー／選択肢を切り替え。同じ数字キーは再利用。判定文を専用領域に配置し、正解マークが数字キーへ出ないよう縦幅を調整。
- `src/game/ui/problem/numberKeypad.ts`: 数字キーをまとめたContainerを返し、切り替え時にまとめて破棄できるよう変更。バトル側の座標は変更なし。
- 背景上の白い面を下端834まで延長し、判定文もその中で読めるよう変更。

保存形式、問題生成、正誤判定、捕獲ゲージの計算、演出時間、素材、依存パッケージは今回変更していません。

## 2026-09-16: プレビュー15番・35番の改善

- 15番 (`clockElapsedMinutes / clockHourMinute / result / analog`): 「○分後」を矢印の上（y268）へ移動。左右の時計の中心はy326、半径48。右の時計は針と答えを示す赤い目印を描かず、中央に「?」を表示。時・分の回答欄は従来どおりy412。
- 35番 (`verticalArithmetic / single / result`): 答えの行をくらいごとの枠へ変更。数字の列間隔48、回答枠42×48、回答の中心y404。上段・下段の数字も同じ列へ配置。次に入力するくらいを青枠で表示。
- ひっ算の結果を答える場合だけ、一 → 十 → 百の順に入力。「けす」は直前に入れたくらいを消し、そこへ戻る。低いくらいの0を保持する。通常の横式、小数、左辺・右辺の穴埋めの入力順序は維持。
- 採点へ渡す文字列は通常の数値順（例: 9 → 0 → 1の入力で`109`）を維持。問題の生成範囲、正誤判定、保存形式は変更なし。
- 各くらいの文字は既存の問題Containerが所有し、次問の描画時に破棄。正解マークの位置は問題表示側から取得し、回答行全体を囲む。
- くり上がり・くり下がりのメモ欄、途中計算ごとの採点は今回追加していない。
