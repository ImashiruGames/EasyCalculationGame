# 「モンスターをつかまえる」直後の画面：レイアウト調査

## 対象と確認方法

ホームの「モンスターを\nつかまえる」は、`MainMenuScene.ts` から `startSceneWithLoading(..., SceneKeys.StageSelect, 'stageSelect', { openCategoryList: true })` を呼びます。

遷移は **ホーム → 読み込み →「ジャンルをえらぼう」** です。保存状態にかかわらずジャンル一覧を開く指定で、ホームから渡すページ番号はないため先頭ページです。その後「みる」で同じ `StageSelectScene` 内のステージ一覧へ切り替わります。

ジャンル一覧を主対象に、関連する学年選択・ステージ一覧・説明パネルも調べました。基準は390×844。コードとCSVの静的調査で、ブラウザ操作や実画面の文字計測は行っていません。文字だけの部分は中心または開始位置を記載し、実測していない高さを断定しません。

表の寸法は枠・ボタンの基本サイズです。枠線や演出の拡大は含みません。ボタンのタッチ領域が見た目より広い箇所は別記しています。

### ページ数と追加への影響

通常のジャンル定義は10種類です。現在の2年生向けは、たしざん・ひきざん・かけざん・時計・□・10のやまの5種類で、2ページです。「ぜんぶ」は10種類で3ページです。

1ページ4件で配列を切り出すため、「長さ」「かさ」を追加しても縦にカードが増え続けることはありません。両方を2年生向けに追加して表示対象になるなら、7種類で引き続き2ページになります。

## 2. ジャンル一覧で見つかった問題

### A. ページ番号と最初のカードが同じY座標

- ページ番号：中心Y=132、中央原点。
- 最初のカード：上端Y=132。
- 描画順も、ページ番号の後にカード背景を作っています。

ページ番号がカード上端をまたぐ配置です。下半分がカード背景に隠れ得ます。これは文字の長さを増やした場合だけの仮定ではなく、**現在のコードにある座標の衝突**です。通常の2年生表示のように複数ページがある場合が対象です。実ブラウザでの見え方の確認とは区別してください。

学年ボタン下端123からカード上端132までは9pxしかありません。ページ番号の中心をこの隙間の下端に置く構成なので、専用の行として十分な高さが確保されていません。

### B. カードの文字と操作ボタンの幅を分けていない

カード中心をYとした内部配置は次の通りです。

| 要素 | 位置 | 設定 |
| --- | --- | --- |
| 名前 | X=50、上端Y−34 | 25px、折り返し・最大幅なし |
| 説明 | X=52、上端Y | 14px、折り返し・最大幅なし |
| 進行状況 | X=52、上端Y＋28 | 13px、折り返し・最大幅なし |
| 「みる」 | X=275〜353、Y−19〜Y＋27 | 幅78、高さ46 |

説明の開始X=52からボタン左端275までの幅は223pxです。名前もボタンと縦範囲が重なる可能性があります。しかし、文字には右側のボタン領域を避ける制限がありません。

既存の短い名称で必ず重なっていると断定するものではありません。「長さ」「かさ」の名前自体は短い一方、説明文や将来の長い名称を追加する際に問題になります。

### C. ヘッダーにも最大文字幅がない

見出しは中央X=195、27px固定です。左右ボタンの見た目の間はX=68〜322（幅254）ですが、タッチ領域の間はX=80〜310（幅230）です。安全な文字領域を決めるなら、ボタンの画像だけでなくタッチ領域も考慮する必要があります。

### カードの状態ごとの差

- プレイ可能：右上に「はいる」、右側に星ランクとプレイ回数。プレイ制限中は入場ボタンを無効化。
- 未解放：右下に「やること」。
- 公開前：右下にComing Soon。
- キャラクターは最大5体で打ち切るため、人数追加で無制限には並びません。

### 文字と右側の情報が重なり得る

名前はX=48、23px、幅制限なし。「はいる」の左端はX=280なので、名前からの幅は232pxです。説明はX=50、15px、幅制限なし。右側の星ランク枠はX=260〜360で、説明の行と縦範囲が近接・重複します。

文字が長いときの縮小や折り返し、その結果増えた高さの確保がありません。今後のステージ名・説明追加で注意すべき点です。

星の説明ボタンはタッチ領域を12pxずつ広げているため、Y=82〜150まで反応します。最初のカード上端138へ12px入りますが、入場ボタンの上端155とは離れており、直ちに二つの操作ボタンが重なっているという意味ではありません。

- 星の説明パネル：幅350（89.7％）、Y=126〜720、高さ594（70.4％）。

## 6. 一時的な読み込み画面

ホームとジャンル一覧の間には `LoadingScene` が入ります。

- 見出し中心Y=318（37.7％）、28px。
- 説明中心Y=366（43.4％）、15px、折り返し幅300。
- 進行バーY=410〜438（48.6〜51.9％）、幅274（70.3％）。
- 割合の文字中心Y=456（54.0％）。

ジャンル件数に応じて項目が増える画面ではありません。主な改善対象は、その後のジャンル／ステージ一覧です。

## 結論

この画面は件数をページで制限しているため、ジャンルやステージを増やした際の縦方向の増加には対応しています。一方、次の二点が弱い構造です。

1. **ヘッダー・ページ番号・一覧の境界**：現在すでにジャンルのページ番号とカード上端が同じ位置です。
2. **カード内の文字と操作の境界**：名前・説明が使える幅と最大行数が決まっていません。

表示領域を定義する際は、上部の操作・ページ情報、一覧カード、下部のページ操作を分け、そのうえで各カード内部を文字領域とボタン領域に分けるのが適切です。4件／3件のページ分割は活用できます。
