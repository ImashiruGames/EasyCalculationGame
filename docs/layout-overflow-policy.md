# 表示領域に入り切らない場合の扱い

作成日: 2026-09-15

実装済みの通常問題画面については、[表示領域と確認結果](capture-layout-implementation.md) を参照してください。

## この資料の位置付け

全画面調査を受けた、レイアウト設計の初版です。今後の修正・新機能で使う基本方針をまとめます。現時点では画面への実装はしていません。

対象画面の番号は [全画面レイアウト確認表](screen-layout-review.md) に合わせます。基準座標は390×844です。具体的な領域の高さ・文字サイズの下限は、各画面の配置を設計するときに決めます。まだ決まっていない数値を、実装の共通定数として先に固定しないことにします。

## 1. 基本方針

1. **学習に必要な情報は省略しない。** 問題文、数式、単位、図のラベル、選択肢、入力した答え、正答が対象です。
2. **操作の領域を確保する。** 本文が増えても、確定・戻る・閉じるボタンを画面外へ押し出さない。文字を隠すだけで解決したことにしない。
3. **文字を際限なく小さくしない。** 決めた下限に達したら、列数や表示方式を変える。下限は実際の端末で読めるかを確認して決める。
4. **一覧と本文を分ける。** 一覧の件数超過はページ送り、詳細の長文は本文欄内の縦スクロールを基本とする。
5. **入り切らない状態を制作段階で見つける。** プレイ中に問題や選択肢を黙って削除・差し替えしない。
6. **画面全体を追加で縮小しない。** 現在の端末に合わせる縮小とは別に、内容を詰めるための全体縮小を重ねない。

## 2. 内容別のルール

| 内容 | 入り切らない場合の順序 | 避ける扱い |
|---|---|---|
| 画面タイトル・モンスター名・ステージ名 | 操作ボタンを除いた幅を確保 → 決めた行数で折り返し → 下限までの縮小 → 詳細表示など、その画面に合う方法で全文を読めるようにする | 閉じるボタンにかぶせる／名前を区別できない省略 |
| 一覧の紹介文・本文の抜粋 | 最大行数まで表示 → 末尾を「…」にする → 詳細で全文表示 | 全文を見る手段のない省略 |
| 問題文・数式・単位 | 意味を保って改行 → より広い問題用配置へ切り替え → 必要なら下限まで縮小 | 「…」／末尾の切り捨て／数値と単位の対応を崩す改行 |
| 語群・選択肢 | 全選択肢に同じ文字サイズを使う → カード内で改行 → 2列から1列へ切り替え | 一部の選択肢だけ縮小／省略／選択肢の数を減らす |
| 回答欄・数字キー・確定操作 | 必要な領域を先に確保 → 問題側の配置を調整する | 問題の長さに合わせてキーを小さくする／入力中にキーを動かす |
| 商品・ステージ・仲間などの一覧 | 現在のページ件数を基本にし、入り切らない追加分は次のページへ | カードを画面下へ足し続ける／カードを極端に小さくする |
| 図鑑メモ・長い説明・会話ログ | 本文欄内を縦スクロール。続きがあることを示し、見出し・閉じる操作は固定 | パネル全体を画面外へ伸ばす／説明を無断で切る |
| お話の会話本文 | 作者が設定するページ分割を優先。既存の長文を救済する方法は下記の専用ルールに従う | 文章の切り捨て／自動で物語の次ページへ進める |
| 購入結果・正誤案内・報酬 | 専用の通知領域に表示。全文が入る改行数を設計時に確保 | 本文・回答・商品カードへの重ね書き |
| キャラ・図・方眼 | 指定領域の中で縦横比を保って拡縮。ラベルと操作可能な大きさも確保 | 縦横を別々に縮める／図だけ収めてラベルをはみ出させる |

一覧での省略は、必要な情報が詳細で読める場合に限ります。購入価格・効果・必要素材など、操作を判断する情報は省略する紹介文に含めません。全文確認の導線がない既存カードには、先に省略だけを導入しません。

## 3. 問題画面のルール（08・12）

### 領域を四つに分ける

- 状態: モンスター、ゲージなど。
- 問題: 問題文、数式、図、図のラベル。
- 回答・操作: 回答欄、語群、数字キー、確定。
- 判定: 正誤や正答の案内。

各領域の内部で内容を配置します。他の領域へはみ出して収めることはしません。特に誤答時は、入力した答えと正答を別の領域に表示します。

横式用、時計・筆算などの縦長問題用、語群用、方眼用の配置を用意する方針です。現在の方眼のように大きい領域を使う問題は、別の配置として扱います。モンスター表示などを減らす必要がある場合は、その変更を個別に検討します。

**解いている最中は、問題の全文と回答操作を同時に見られることを優先します。** 問題本文や選択肢をスクロール・ページ送りにすることは通常の解決策にしません。想定した配置に入らない問題は制作段階で修正します。将来、長文読解などを追加するときは専用の画面として設計します。

判定領域の確保を理由に、解答時間、タイマー、バトル進行、通知の表示時間を無断で変えません。配置は問題を表示する前に決め、回答中のキー位置は固定します。

### 「長さ」「かさ」への適用例

**読み方の語群問題**

- 問題文: `cm の よみかたは？`
- 選択肢: `センチメートル`、`ミリメートル`、`ミリリットル`、`デシリットル`
- 2列で四つの語を無理なく読めなければ、1列4行へ切り替える。
- 全選択肢を同時に表示する。最も長い語に合わせて全カードの文字サイズ・高さをそろえる。文字の切り詰めや選択肢ごとの縮小はしない。

**計算問題**

- 問題: `3 cm + 2 cm = □ cm`
- 数字キーと確定操作は固定した領域を使う。
- `3 cm`、`2 cm`、`□ cm`をそれぞれ意味のまとまりとして扱う。単位だけを次の行へ送らない。
- この資料では出題や正誤判定の追加は行わない。選択式と数字入力を同じステージに入れる場合は、問題ごとに入力方式を切り替える対応も必要。

## 4. 一覧・詳細・通知のルール

### 一覧（02・06・11・13-1・14・15・16・20・23）

- ヘッダー、通知、カード一覧、ページ操作の範囲を分ける。
- カード内も「アイコン」「文字」「操作」を分け、文字の右端を操作ボタンの手前にする。
- 既存のページ件数は、カードとページ操作の両方が入る限り維持する。種類の違うカードに一律「4件」を当てはめない。
- 通知の有無でカードやページ操作が跳ねないよう、通知が出る一覧では最初からその場所を確保する。
- ページ数が変わっても有効なページを表示し、選択状態や購入後の位置を可能な範囲で維持する。

### 詳細（13-2など）

見出し・閉じる操作を固定し、説明と技などの本文だけをスクロール対象とします。本文に含まれるリンクやボタンを実装する場合は、ドラッグによるスクロールとタップを区別し、領域外の項目にタップが届かないようにします。

### 通知（09・12・14・26など）

通常の短い通知は指定した行数内に全文を表示します。名前・数値・報酬数も含めた最長パターンを設計時に扱います。長い報酬一覧が必要なら、件数だけに省略して消すのではなく、全文を確認できる結果パネルを設計します。

## 5. お話・制作・引き継ぎ

- **お話（19・21・22）:** 新規制作では再生枠の幅・高さ・ルビを基準にページを分ける。編集欄で全文を入力できることを、再生時に収まる保証にしない。
- **既存のお話:** 保存済み本文やページ構成を自動で書き換えない。長文への救済は、同じ物語ページ内での表示分割を候補とする。分割してもキャラ演出・音・既読処理を再実行せず、最後の表示を読み終えてから物語の次ページへ進む必要がある。タップ操作への影響があるため、再生UIの具体案を作ってから適用を決める。
- **制作ツール（21・24）:** 作業領域と操作欄を分ける。操作が増えたら操作欄のタブやページに分け、ボタンを端からはみ出させない。方眼はラベルと枠線も含めて作業領域に収める。
- **タイトル編集（01・17）:** 既存の飾り方を保つ。画像の外周と開始案内の位置が分かるガイドを候補とし、保存済みの位置・大きさを強制修正しない。
- **HTML入力（18・21・24）:** 見える高さに合わせて入力パネルの最大高さを決め、必要ならパネル内を縦スクロールできるようにする。キーボード表示中にも入力欄と確定・閉じる操作へ到達できることを手動で確認する。

## 6. 実装時の確認基準

- 文字数だけではなく、実際のフォント・折り返し・ルビを含む表示幅と高さで判断する。
- 本文・カード・操作の範囲が重ならない。枠線と選択状態の強調にも余白を用意する。
- 表示枠だけでなく、タップ判定も領域内に収まる。
- 正常時だけでなく、誤答、長い名前、最大桁数、報酬増加、項目なし、最終ページを考慮する。
- スクロールやページ操作が加わっても、選択済みの答えやゲーム状態を失わない。
- 390×844で収まることと、端末で読めて押せることを分けて確認する。文字の下限はゲーム内座標だけで決定しない。
- 新しい省略やページ送りで重要な情報・操作が消えるなら、その実装を完成扱いにしない。

## 7. 適用する順序

1. **14-1 ショップ:** 通知と商品領域を分離する。追加商品にはページ送りを用意する。基本ルールを小さい範囲で適用できる。
2. **08・12 問題画面:** 回答方式ごとの領域を設計し、問題と判定の高さを確保する。既存の全回答パターンを基準にする。
3. **06・20などの一覧:** ページ番号、文字、操作の領域競合を解消する。
4. **13-2 図鑑:** 長い説明を読むための本文スクロールを設計する。
5. **21・24 制作画面:** 作業領域と操作欄を分離する。
6. **22などのお話:** 既存のページ・演出・タップ操作を保つ具体案を作ってから適用する。

次の設計作業では、この方針を各画面の具体的な矩形・余白・文字サイズ・最大行数へ落とし込みます。今回の資料作成で既存の画面、保存形式、ゲームバランスは変更していません。
