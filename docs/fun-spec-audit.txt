一桁計算練習アプリ
楽しさと、それを邪魔しそうな仕様の棚卸し
作成日: 2026-05-25

方針:
- コード修正は行わず、現状仕様の観察だけをまとめる。
- 画面名、ID、数値はコード上の定義を根拠にする。
- このファイルはUTF-8で作成する。


概要
====

このアプリの楽しい核は、かなりはっきりしています。

1. 問題を解いてゲージをため、ボールを投げてキャラクターを捕まえる。
2. 捕まえたキャラクターが図鑑、ステージカード、リザルト、トロフィーに残る。
3. かぶり捕獲が「かけら」になり、進化やアメ交換につながる。
4. 集めたキャラクターを対戦で使い、コインやアメを得る。
5. ステージ解放、レア発見、進化、ランクアップで長期目標が増える。

一方で、楽しさを邪魔しそうな大きなリスクもあります。

- 新しいステージなのに、捕まえられるキャラクターがすでに埋まっている。
- 0.5%レアと10分あたり10回制限が組み合わさり、コンプリートがかなり遠く見える。
- ステージ解放に必要な捕獲回数が、キャラクター集めの新鮮さより先に尽きる場合がある。
- 「ステージを全部集めた」の判定が、ステージカード、トロフィー、実際のプレイ履歴で少しズレる。
- 対戦やショップが便利な反面、コレクションだけを楽しみたい子には別モードを強制された感じになり得る。

特に、ユーザーさんの例に近いのは「かけ算カテゴリ」と「一部のひき算後半」です。
学習内容としては新ステージでも、コレクション報酬としては既出キャラが多く、モチベーションが落ちる可能性があります。


調査で見えた楽しさ
==================

1. 捕獲そのものが短い達成になっている
------------------------------------

主な根拠:
- src/game/scenes/CaptureGameScene.ts
- src/game/speedBonus.ts
- src/game/ui/captureBall.ts

楽しい点:
- 正解すると捕獲ゲージが伸びる。
- 速く答えると 2倍 / 1.5倍 のスピードボーナスがある。
- ゲージが満タンになると、ボールを上にスワイプして投げる演出がある。
- 捕獲成功時にキャラクター表示、ファンファーレ系の演出、NEW表示がある。
- 捕獲モードでは、遅いこと自体に罰がない。これは計算練習としてかなり良い。

邪魔しそうな点:
- 捕獲が「新キャラ」ではなく「既出キャラ」ばかりになると、この短い達成の価値が下がる。
- スピードボーナスは楽しいが、速さが苦手な子には「速くないと損」と感じられる可能性はある。ただし捕獲モードでは罰ではなくボーナスなので、現状は比較的安全。


2. キャラクター集めが前面に出ている
----------------------------------

主な根拠:
- src/game/scenes/StageIntroScene.ts
- src/game/scenes/StageSelectScene.ts
- src/game/scenes/BgmPreviewScenes.ts
- src/game/scenes/ResultScene.ts
- src/state/save.ts

楽しい点:

- 捕獲済みなら名前と姿が見える。
- 図鑑は 110体。
- 直接ステージに出るキャラは55体で、残りは主に進化で増える構造。
- メインメニューに総捕獲数と種類数が出る。
- リザルトで捕獲数、かけら数、進化までの残りが見える。

邪魔しそうな点:
- 「このステージにはまだ未発見がいる」と分かるのは楽しいが、逆に全員既出だとステージに入る前からワクワクが減る。
- ステージカードの小さいアイコンだけでは、「このステージで新規が何体いるか」「進化素材としてどれくらい意味があるか」は瞬時に伝わりにくい可能性がある。


3. かぶりに意味がある
--------------------

主な根拠:
- src/state/save.ts
- src/state/evolution.ts
- src/game/scenes/ResultScene.ts
- src/game/scenes/EvolutionScene.ts
- src/game/scenes/BgmPreviewScenes.ts

楽しい点:
- 通常キャラのかぶりは、進化ファミリーのかけら +1。
- レアキャラのかぶりは、かけら +5。
- 進化に必要なかけらは 6 / 8 / 14。
- かけら5個をアメ1個に交換できる。
- アメ1個を30コインに交換できる。

この仕様は「かぶり=完全なハズレ」を避けるためにかなり重要です。

邪魔しそうな点:
- かぶりの価値は、キャラクターそのものの新鮮さよりは弱い。
- 進化先がない、または進化が終わったファミリーでは、かぶりが素材管理に近くなる。
- 小さい子にとっては「同じ子が出たけど、進化に近づいた」という納得が演出だけでは足りない可能性がある。


4. ステージ解放が長期目標になっている
------------------------------------

主な根拠:
- src/data/stages.ts
- src/state/progression.ts
- src/game/scenes/StageSelectScene.ts

楽しい点:
- ステージにはカテゴリがある: addition / subtraction / multiplication / makeTen。
- ステージごとに問題ルール、背景、出現キャラ、解放条件が違う。
- 解放条件には、特定ステージの捕獲回数、図鑑種類数、特定キャラ捕獲、トロフィーなどがある。
- ロック中のステージは、条件と残り数が表示される。

邪魔しそうな点:
- 解放条件の多くは「そのステージで何回捕獲したか」なので、すでに新キャラがいなくても同じステージを繰り返す必要がある。
- 30回、8回、10回などの条件は、学習の反復としては意味があるが、コレクション目的では作業感になり得る。
- ステージプレイ制限と組み合わさると、必要回数を進めたい時に待ち時間が発生する。


5. 対戦で「集めた後」の使い道がある

邪魔しそうな点:
- 対戦は相手の自動攻撃タイマーがあり、捕獲より緊張感が強い。
- コインやアメが欲しいだけのプレイヤーには、対戦が別ジャンルの負担に感じられる可能性がある。
- 計算練習が苦手な子ほど、対戦報酬に届きにくくなる可能性がある。

主な根拠:

特に注意したい阻害仕様
======================

1. 新規キャラが少ない、またはゼロのステージがある
------------------------------------------------

前提:
- 下の数値は、ステージ定義の並び順を基準に「それ以前のステージに出ていないキャラ」を新規として数えたもの。
- 実際にはプレイヤーがどのカテゴリから遊ぶかで体感は変わる。
- ただし、足し算やひき算を先に進めた後でかけ算へ入ると、ユーザーさんの指摘どおり「新ステージなのに既出ばかり」が起きやすい。

全体:
- ステージ数: 29
- 直接出現するキャラ種類: 55
- 図鑑全体: 110
- 直接出現枠の合計: 123

カテゴリ別の傾向:
- addition: 8ステージ / 出現35枠 / 新規29 / 新規ゼロ0ステージ
- subtraction: 10ステージ / 出現44枠 / 新規17 / 新規ゼロ2ステージ
- multiplication: 9ステージ / 出現35枠 / 新規3 / 新規ゼロ7ステージ
- makeTen: 2ステージ / 出現9枠 / 新規6 / 新規ゼロ0ステージ

新規ゼロになり得るステージ:
- subtractionForest
- borrowRidge
- timesTable1
- timesTable3
- timesTable4
- timesTable5
- timesTable6
- timesTable8
- timesTable9

ほぼ既出になり得るステージ:
- teenMinusBridge: 新規1 / 既出4
- borrowCliff: 新規1 / 既出4
- timesTable7: 新規1 / 既出3

影響:
- 新しい計算ルールを練習する動機は残る。
- ただし「新キャラを捕まえたい」という動機は弱くなる。
- 特にかけ算は、学習上は9段階の進行があるのに、コレクション上の新鮮さが薄く見える。
- ステージカード上で全員捕獲済みに見えると、入る前から期待値が下がる。

重さ:
- 高。キャラクター集めを主目的にしているプレイヤーにはかなり効く。


2. レア0.5%とプレイ制限の組み合わせが重い
---------------------------------------

主な根拠:
- src/data/stages.ts
- src/data/monsters.ts
- src/state/save.ts
- src/game/scenes/StageIntroScene.ts

現状:
- 0.5%のレア枠が複数ステージにある。
- 例: sunomaru, goropeka, mizukira, hoshimimi, komorebi, achichin, kiramekisama, rainbow など。

- レアベルを使うと、レアがいるステージではレアを確定で出せる。
- レアベルはログイン7日目でもらえるが、ショップ価格は1000コイン。
- ステージ捕獲は、同一ステージごとに10分間で10回まで。

体感の問題:
- 0.5%は、単純期待値で約200回に1回。
- 10回挑戦しても出る確率は約4.9%。
- 30回挑戦しても出る確率は約14%。
- 100回挑戦しても出る確率は約39%。
- 200回挑戦しても出る確率は約63%。

ステージ制限を考えると、レアベルなしで狙うのはかなり遠いです。
「いつか出るかも」のワクワクより、「今日も出なかった」が勝つ可能性があります。

重さ:
- 高。コンプリートを目指す子ほど強く感じる。

重さ:

====================

----------------------------------

理由:
- multiplication は9ステージあるのに、足し算やひき算を先に遊んだ後だと新規キャラがほとんど残らない。
- 学習内容は新しいので、ここにコレクション上の新鮮さが少し足されるとかなり効きそう。

特に注意:
- timesTable3, 4, 5, 6, 8, 9 は既出のみになり得る。
- timesTable7 も新規1体だけ。

- ただし0.5%とステージ制限の組み合わせは重い。
- レアベルは良い救済策だが、1000コインは高い。

注意:
- レアを「本当にレア」にしたい意図は分かる。
- 問題は確率そのものより、「外れ続けた時に何か進んでいる感覚」が足りるかどうか。

理由:

注意:
- 反復条件を減らすべき、という意味ではない。
- 「反復したくなる報酬」が同時にあるかを見るのが大事。

----------------------------------------

理由:
- コレクションゲームでは「埋まった」「制覇した」の意味がかなり大事。
- 今はステージカード、トロフィー、実際のステージ捕獲履歴が少し違う。

注意:
- どれが正しいかより、プレイヤーに同じ言葉で見せるかどうかが重要。


5. かぶり時の喜びの強さ
----------------------

理由:
- かぶりが進化素材になる設計は良い。
- ただし新規キャラ不足を支えるには、かけら獲得や進化接近の見せ方が十分強い必要がある。


具体的な「楽しさを邪魔する組み合わせ」
====================================

組み合わせA:
新ステージ + 出現キャラ全員既出 + 解放条件の周回

起きそうな感情:
「問題は新しいけど、捕まえる楽しみがない」
「次のステージのためにやっているだけ」

該当しやすい場所:
- subtractionForest
- borrowRidge
- timesTable3以降の多く


組み合わせB:
ステージ制覇したい + 残りが0.5%レア + 10分10回制限

起きそうな感情:
「あと1体なのに全然出ない」
「今日はもうこのステージを遊べない」

救済はある:
- レアベル

ただし:
- レアベルが1000コインなので、救済に届くまでが遠い可能性がある。


組み合わせC:
かぶりが続く + 進化まで遠い + NEWが出ない

起きそうな感情:
「また同じ」
「かけらは増えたけど、何が嬉しいのか分かりにくい」

支えている仕様:
- リザルトで進化までの残り表示
- 進化可能ボタン
- アメ交換

注意:
- かぶりの意味はあるが、感情的にはNEWより弱い。


組み合わせD:
トロフィー解除 + ステージカード未完成、または未プレイ

起きそうな感情:
「ぜんぶって出たのに、何がぜんぶ？」
「このステージまだ遊んでないのに達成扱い？」

該当理由:
- トロフィーのstage-completeは、キャラをどこで捕まえたかを見ない。
- ステージカードは進化ライン最終形まで見る。


追加仕様案: 連続出現の抑制となかまよび
====================================

狙い
----

「また同じキャラ？」という体感を減らしつつ、レア枠や既存の重み付き抽選を大きく壊さないための仕様。

完全に同じキャラを禁止するのではなく、直近で連続して出ているキャラだけを少しずつ出にくくする。
これにより、かぶりは残るが、かぶり続ける確率は自然に下がる。


通常抽選の仕様
--------------

既存のステージ出現重みを基本にする。

直近で出たキャラと同じキャラを抽選候補にする場合だけ、重みを半減する。

- 直近1回で出たキャラ: そのキャラの重みを 1/2 にする。
- それでも同じキャラが出て2回連続になった場合: 次回はそのキャラの重みをさらに半減し、元の 1/4 にする。
- それでも同じキャラが出て3回連続になった場合: 次回はそのキャラの重みをさらに半減し、元の 1/8 にする。
- 以後も、同じキャラが連続するたびに 1/16、1/32、1/64... と半減していく。
- 違うキャラが出た場合は、前のキャラの低下はリセットされる。
- 新しく出たキャラが、次回の「直近1回で出たキャラ」になる。

式で書くと、直近キャラの連続出現回数を n として:

- 直近キャラの調整後重み = 基本重み * 0.5^n
- それ以外のキャラの重み = 基本重み

例:
- Aが1回出た直後: 次回のAは 1/2。
- Aが2回連続で出た直後: 次回のAは 1/4。
- Aが3回連続で出た直後: 次回のAは 1/8。
- そこでBが出たら、Aは元の重みに戻る。次回はBだけが 1/2。


この仕様のよいところ
--------------------

- 「同じキャラが絶対出ない」わけではないので、確率抽選の自然さが残る。
- レア枠を未捕獲優先などで直接押し上げないため、レア率が不自然に上がりすぎにくい。
- 既出キャラにも進化素材としての意味が残る。
- 連続かぶりだけを抑えるので、プレイヤーの不満になりやすい部分に絞って効く。
- 1ステージの候補数が少ない場合でも破綻しにくい。

注意:
- 正規化後の確率としては、直近キャラ以外のキャラが少しだけ出やすくなる。
- ただし、直近キャラ1体だけを下げる方式なので、レアを直接優遇する仕様より影響はかなり小さい。


なかまよびアイテム
------------------

なかまよびアイテムを使った場合は、通常抽選をせず、指定された同じキャラが100%出るようにする。

想定する使いどころ:
- 進化に必要なかけらを集中的に集めたい。
- 好きなキャラをもう一度出したい。
- あと少しで進化できるキャラを狙いたい。
- かぶりを「嫌な事故」ではなく「自分で選んだ目的」に変える。

仕様上の扱い:
- なかまよびで出たキャラも、実際に出たキャラとして連続履歴に入れる。
- そのため、なかまよび後に通常抽選へ戻ると、そのキャラは連続回数に応じて出にくくなる。
- これにより、アイテムで集中して集めた後は、自然に別キャラへ戻りやすい。

対象キャラの決め方は、実装時に決める余地がある。
候補としては以下。

- 直前に出たキャラをもう一度呼ぶ。
- そのステージに出る捕獲済みキャラから選ぶ。
- そのステージに出る全キャラから選ぶ。

この中では、「直前に出たキャラをもう一度呼ぶ」か「捕獲済みキャラから選ぶ」が安全そう。
未発見キャラやレアを自由に指定できると、図鑑発見やレアベルの役割が弱くなる可能性がある。


レアベルとの役割分担
--------------------

レアベル:
- レアがいるステージで、レアを出すためのアイテム。
- 低確率レアの救済策。

なかまよび:
- すでに狙いがあるキャラを、もう一度出すためのアイテム。
- 進化素材集め、好きなキャラ集めの補助。

役割を分けるなら、なかまよびは「未発見レアを直接呼べない」ほうがバランスを保ちやすい。
ただし、直前にレアが出た後に使える仕様にするなら、「せっかく出会えたレアをもう少し集める」ごほうびとしては気持ちよい。


補足メモ
========

1. かぶり自体は悪い仕様ではない
------------------------------

このアプリでは、かぶりは進化素材、アメ、コインにつながる。
なので「かぶりをなくす」方向より、「かぶっても嬉しいことが伝わる」「新規がないステージにも別のごほうびがある」方向が合いそう。


2. 学習目的と遊び目的が時々ぶつかる
--------------------------------

同じ問題形式を何回も解くことは学習には良い。
でも、ゲームとしては同じ場所、同じキャラ、同じ報酬が続くと弱くなる。

このアプリは学習アプリなので、反復を消す必要はない。
ただし、反復を楽しく見せる報酬設計が重要。


3. 文字表示について
------------------

今回の主題ではないが、ソースや一部監査メモを読むと、日本語文字列が文字化けして見える箇所がある。
実際のゲーム画面でも文字化けしている場合、楽しさ以前に大きな阻害要因になる。
ただし、今回のレポートでは仕様評価を主目的にし、文字化け修正は扱っていない。
