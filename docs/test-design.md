# テスト設計メモ

## 1. パラメータと値の洗い出し

今回の対象は、画面描画やPhaser依存を避け、純粋ロジックに寄せました。

| 対象 | 主な入力条件 | 値 |
| --- | --- | --- |
| 問題生成 | operator | plus, minus, times, *, × |
| 問題生成 | left/right/result | 0, 1..9, 10..99, 空欄, 逆順範囲 |
| 問題生成 | answerSlot | left, right, result |
| 問題生成 | digitRule | なし, noBorrow, borrowRequired |
| 速度ボーナス | elapsedMs | 0, 999, 1000, 2999, 3000 |
| バトル | 属性相性 | 有利, 不利, 通常 |
| バトル | 倍率 | 速度倍率, 基礎倍率, 最小ダメージ |
| 進化進捗 | 必要かけら | null, 必要数あり |
| 進化進捗 | 所持かけら | 0, 必要数-1, 必要数, 必要数+1 |
| ステージ解放 | 条件状態 | 条件なし, 未達, 達成, Coming Soon |
| セーブ | 保存データ | 未保存, 壊れたJSON, 既知ID, 未知ID, 端数, 0以下 |
| ログイン | 日付関係 | 未受取, 同日, 前日, 日付飛び |
| プレイ制限 | 窓と回数 | 有効窓, 期限ちょうど, 上限-1, 上限 |

## 2. 同値分割・境界値分析

同値クラスは「正常な入力」「候補なしになる入力」「永続化時に捨てる入力」に分けました。境界値は、桁入力上限の99、速度ボーナスの1000ms/3000ms、プレイ制限の10回/10分、進化素材の必要数ぴったりを採用しています。

## 3. 禁則条件の例外

問題生成では、空欄が2つ以上ある組み合わせは使用上成立しないため、通常ケースから除外し、例外ケースとしてフォールバックだけ確認しました。digitRuleは減算にだけ意味があるため、加算/乗算との全組み合わせは除外しています。セーブの未知IDや0以下の数値は正規化で破棄される入力として扱いました。

## 4. ペアワイズ法・直交表の適用

全組み合わせではなく、以下の代表ケースで2因子間の関係を押さえました。実装は `tests/run.mjs` のテーブル駆動テストです。

| ケース | operator | 空欄 | 範囲 | digitRule | 期待 |
| --- | --- | --- | --- | --- | --- |
| result slot plus zero boundary | plus | なし | 0境界 | なし | 0 + 0 = □ |
| left blank make-ten | plus | left | 1..9/10 | なし | □ + 9 = 10 |
| right blank make-four | plus | right | 固定値 | なし | 2 + □ = 4 |
| multiply alias | * | なし | 9境界 | なし | 9 × 9 = 81 |
| reversed range | plus | なし | 逆順 | なし | 範囲を正規化 |
| noBorrow | minus | なし | 2桁-1桁 | noBorrow | 繰り下がりなし |
| borrowRequired | minus | なし | 2桁-1桁 | borrowRequired | 繰り下がりあり |
| forbidden blanks | plus | 2つ | 10固定 | なし | フォールバック |

実行コマンド:

```powershell
npm test
npx tsc --noEmit
npm run build-nolog
```
