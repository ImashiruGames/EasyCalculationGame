# コード構造の整理と確認結果

## 方針と対象

作業開始時に `first-read.txt`、各フォルダ案内、設定、初期化、Scene、出題、保存、素材、UI、入力、音、終了処理を調査しました。作業開始時から存在した未コミットの変更を基準にし、それらを巻き戻さずに整理しています。

`package.json` の実際の依存は **Phaser 4.0.0 / TypeScript 5.7系 / Vite 6系** です。元テンプレートの名称にある Phaser 3 とは異なります。ライブラリの更新や追加はしていません。

ゲームのルール、出題の確率、保存キー・保存形式、表示文言、座標、色、音量、演出時間、Sceneキーを維持する方針です。CSV、画像、音声、Viteの相対パス設定、package-lock.jsonは変更していません。ビルド生成物のdistは更新されています。

## 変更した構造

### 問題の生成・判定と表示

- `src/game/problem/mathProblems.ts` は既存の公開関数を再エクスポートする入口です。呼び出し側は従来のimportを続けられます。
- `problemGeneration.ts` がルール選択と直前の問題の回避を担当します。
- `integerProblems.ts`、`clockProblems.ts`、`fractionProblems.ts`、`squareRootProblems.ts` が種類ごとの生成を担当します。
- `problemNumbers.ts` は共通の数値処理、`problemKinds.ts` は型ガード、`problemFormatting.ts` は文字列化、`problemAnswers.ts` は正誤判定です。
- `choiceAnswers.ts` は選択肢を作ります。Phaserのシャッフルを外から渡すため、Sceneなしで扱えます。
- `answerInput.ts` は入力桁数、`gridGeometry.ts` は方眼の範囲・長方形判定です。
- `src/game/ui/problem/CaptureProblemView.ts` が問題と回答欄の描画を所有します。Sceneから問題と表示用の入力状態を受け取ります。
- `src/game/ui/problem/gridExpression.ts` は捕獲・バトルの方眼描画を共用します。両画面の位置・サイズ・文字サイズの違いは引数で保持しています。

`CaptureGameScene` は約4,064行から約1,599行になりました。行数削減そのものではなく、進行・入力と問題表示を分けたことが主な改善です。問題表示の既存描画順と回答欄への演出用アクセスも保持しています。

### 保存

`src/state/save.ts` は公開APIの入口として残し、実装を既存の `src/state/save` フォルダへ分けました。

| ファイル | 責務 |
| --- | --- |
| storage.ts | localStorageの読み書き |
| selectors.ts | 保存状態からの値の取得 |
| progressActions.ts | 捕獲・進行・バトル・引き継ぎ |
| inventoryActions.ts | 持ち物・進化・購入・図鑑・タイトル |
| dailyRewards.ts | ログイン・日次ミッションの報酬 |
| playEntries.ts | プレイ制限・入場記録 |
| debugActions.ts | 開発用の状態変更 |

既存の正規化・移行・報酬計算は維持しました。保存処理の分割は、元の69関数すべてで関数本体が同一です。

### その他の画面と共有処理

- 図鑑、ショップ、従来のバトル入口をそれぞれ別ファイルに分割しました。`DexPreviewScenes.ts` は互換性を保つ再エクスポートの入口です。
- お話の下書き・ページ・配置物の複製を `state/storyCreator.ts` に集約しました。編集、一覧、プレビューで同じ複製処理を使います。
- `state/browserStorage.ts` にlocalStorageの利用可否の取得を集約しました。ブラウザがプロパティへのアクセス自体を拒否する場合も処理できます。
- 各フォルダ案内と `first-read.txt` を更新しました。新しいフォルダは作っていません。

## 主な問題点とPhaser固有の改善

| 元の問題 | 改善 |
| --- | --- |
| shutdownとdestroyに別々の一度きりハンドラを登録し、再入場ごとにdestroy側が残る | `onSceneExit` が両方を解除して後始末を一度だけ実行 |
| コピーやファイル読み込みの結果が、退場後や再入場後のSceneに戻る | 入場ごとのAbortSignalを保持し、古い結果を破棄 |
| ログイン報酬をタップで閉じてもEnter・Spaceの待機が残る | 最初の入力で競合する待機をすべて解除 |
| プレイ制限の再確認ごとにshutdownハンドラが増える | Phaser Clockによる終了処理に任せ、表示の早期破棄時だけ個別解除 |
| 文字や報酬表示を破棄しても、それを対象とするTweenが残り得る | 表示物と子要素のdestroyにTween停止を連動 |
| 引き継ぎのDOM入力フォーカスが画面の寿命から独立 | Sceneタイマーに移し、対象DOMの一致も確認 |
| メニューを閉じた後の遅延処理がボタンを再作成し得る | 表示コンテナの生存を確認 |
| お話の試聴音がSceneを離れても残り得る | Scene終了時に音を破棄し、自然終了時は終了ハンドラも解除 |
| AudioContext再開待ちの間に曲が変わると古い曲へ戻り得る | 再開時にContext・希望曲・ページの表示状態を再確認 |
| ゲーム破棄時にBGM、DOMリスナー、画像先読みが残る | ゲームdestroy時にまとめて解除し、開発時のモジュール破棄も接続 |

通常のScene遷移でゲーム全体のBGMや画像先読みを止める変更はしていません。音の終了時にはOscillatorとGainの接続も解放します。

## TypeScriptと削除した重複

- 回答欄の表示用状態、選択肢、シャッフルの型を明示しました。
- 回答位置の候補を型付きタプルにし、位置を取り出す際の型アサーションを除去しました。
- 型ガードと回答判定を分離し、問題種類の追加時に変更箇所を探しやすくしました。
- 重複していた方眼の描画・幾何処理、下書き複製、localStorage取得、不要になったimportと元Scene内の移動済み実装を削除しました。
- 移動した関数の既存コメントは手掛かりとして保持し、説明のなかった関数と新規関数に役割のコメントを付けました。
- 用途を断定できないSceneや素材の一括削除はしていません。

## 確認結果

段階ごとにTypeScriptとビルドを確認し、最後に再度実行しました。

| 確認 | 結果 |
| --- | --- |
| `npm run typecheck` | 成功。`tsc --noEmit`を実行するコマンドを追加 |
| `npm test` | **122件成功**。既存109件と追加13件 |
| `npm run build-nolog` | 成功、終了コード0 |
| lint | プロジェクトにlintスクリプトなし。追加のツール導入なし |
| `git diff --check` | 成功 |
| 内部import・再エクスポートの依存確認 | 124モジュール、588参照、循環依存なし |

追加13テストは `tests/refactor.mjs` にあります。再入場25回のイベント解除、古い非同期結果、入力競合、保存アクセス拒否、深い複製の独立性、各種選択肢、方眼、入力桁数を確認します。

作業開始時のソースを基準に、次の差分検証も実施しました。

- **1,308件の固定乱数による比較**：実在97ステージと追加12種のルート問題ルールについて、生成結果、直前問題の回避、問題・答えの文字列、正誤判定、乱数の呼び出し回数が一致しました。
- **97ステージの連続した問題表示の比較**：元Sceneと分離後のViewを記録用の代替Scene上で動かし、表示物の生成・更新・破棄命令と引数が一致しました。文字幅は決定的な代替計測です。実ブラウザのレンダリング比較ではありません。
- 元の出題モジュールの119関数は関数本体が同一です。残り1関数は回答位置の型付きタプルへの変更で、上記の結果比較でも一致しています。

ブラウザ自動操作、実機操作、画像比較は行っていません。したがって、ブラウザ固有の実行時エラーや実際の見た目・操作感までは確認済みとしません。一時的な比較スクリプト・ログ・開始時ソースの控えは作業後に削除し、通常の回帰テストを残します。

## 残っている課題

1. **お話エディタと問題表示の規模**：StoryCreatorSceneは約3,750行、CaptureProblemViewは約2,070行あります。前者のパネル分割、後者の問題種別ごとの表示分割は次の候補です。今回は描画・操作の結び付きが強い箇所の追加再設計を控えました。
2. **保存失敗の返し方**：一部の進行更新は保存失敗を戻り値で伝えず、お話保存にも失敗時の通知が統一されていない箇所があります。これを揃えるとゲーム進行・UIの失敗時挙動も変わるため、今回は保存処理の既存契約を維持しています。
3. **従来のBattlePreviewScene**：起動時の登録はありますが、現在の通常の遷移先には見つかりませんでした。外部からの利用を断定できないため残しました。
4. **配置済みファイル**：ルートやdocs内にある配布物・古い素材候補は、公開用途を断定できないため削除していません。
5. **出題候補の列挙**：候補配列の作成が大きくなり得る処理は残っています。実測なしの高速化や、抽選の分布・乱数順を変える最適化は行っていません。

### 手動で確認する箇所

- タイトルからステージ選択、ゲーム開始、正誤判定、捕獲、結果、図鑑、ショップへの移動。
- 時計、分数、ルート、筆算、方眼、各種選択肢の入力と表示。方眼は捕獲・バトルの両方。
- ログイン報酬をタップで閉じた後のEnter・Space操作。
- お話の編集、複製、プレビュー、JSON取り込みと、取り込み中の画面移動。
- 引き継ぎコードのコピー・入力をしたまま戻る操作と再入場。
- BGM・SE、タブの非表示からの復帰、スマートフォンのタッチとPCのキー入力。
- 相対パスで公開した環境での画像・音声・PWAの起動。
