# 通常の計算・捕獲画面：全回答方式の縦配置調査

## 調査の範囲と数値の読み方

対象は `CaptureGameScene` の出題中の画面です。バトル画面、登場・捕獲・結果演出、メニューの一時表示は別レイアウトなので含めません。

次を読み合わせて調査しました。

- `src/game/types.ts` の問題種類15種、回答方式13種、ルートのモード12種。
- `CaptureProblemView.ts` の全描画分岐と、その補助描画関数。
- `CaptureGameScene.ts` のヘッダー、モンスター、選択カード、回答ボタン。
- `layoutConfig.ts`、`numberKeypad.ts`、`button.ts`、`textureCache.ts`。
- 通常の出題設定279行と、デバッグの出題設定40行。生成時に回答方式を補う処理も確認。
- 面積・筆算・虫食い算・4種の選択式は現在デバッグ側に配置されています。将来の追加に関係するため、これらも含めています。

**基準画面は390 × 844です。縦の比率はすべて844を100％としています。** ブラウザ全体の高さに対する比率ではありません。画面全体はFITで拡縮されます。

- 「位置」は画面上端からの位置、「高さ」はその部分の占有量です。位置35％と高さ35％は意味が異なります。
- 表の範囲はコードが指定する枠・円・ボタンの幾何寸法です。線の太さ、影、演出中の拡大は、明記した場合を除き含めません。
- 数式の横幅に応じて縮小する方式は、縮小率1の寸法を記載します。実際の問題によって枠が小さくなることがあります。
- 文字はフォント計測で高さが変わります。文字だけの部分は**中心位置・文字サイズ・行数**を記載し、実測していない上下端を確定値として扱いません。
- コードと設定の静的調査です。ブラウザ自動操作、スクリーンショット、実機での文字寸法測定、ゲームのテスト実行は行っていません。

## 9. 確認できた境界の問題

### 数字キーとの間隔が足りない方式

数字キーの入力領域はY=408からです。枠線・影を除いたコードの寸法でも、次の状態です。

| 方式 | 回答枠下端 | キー上端との差 | 解釈 |
| --- | ---: | ---: | --- |
| 通常横式 | 最大326 | 82空く | 縦方向には余裕がある |
| 通常分数 | 最大341 | 67空く | 下側には余裕がある |
| 虫食い算 | 400 | 8空く | 小さい余白 |
| 面積を答える | 403 | 5空く | 枠線も考えると余裕が少ない |
| 筆算 | 409 | 1入る | 中央キーと回答枠は横方向にも重なる位置 |
| 経過した分・時間 | 412 | 4入る | 縦方向の範囲が重なる |
| 何分後の時刻を二枠回答 | 最大418 | 最大10入る | 縮小率次第。未縮小では縦範囲が重なる |

これは静的な矩形・配置値の比較です。色の見え方や実際の重なりの見え方をブラウザで確認したという意味ではありません。枠線や選択強調を加えると、必要な余白はさらに増えます。

### モンスターパネルとの境界

- パネル下端は244。経過時間の時計本体は上端232なので、Y方向で12px（画面高の1.4％）パネル内へ入ります。
- 有理化のルート線は未縮小で上端228。パネル内へ16px（1.9％）入ります。
- ルート比較の説明文の中心234自体がパネル内です。捕獲ゲージ中心222にも近い位置です。
- 通常分数の上側回答欄は247からで、パネルとの隙間は3px。二枠回答の青枠や線の厚みまで含めると、余裕はさらに小さくなります。
- 方眼は重ね表示する別構成です。上の例と同じ「少しはみ出した問題」として直すべきではありません。

### 高さ管理がない部分

- 複数行の説明文と正誤メッセージに、共通の最大高さがありません。
- 数式の横幅を測って縮小する仕組みはありますが、前後の領域との縦方向の衝突判定はありません。
- 横幅の縮小、文字サイズの下限、分子と分母の間隔が別々のルールなので、常に同じ比率で縮小されるわけではありません。

### 今後、回答方式を混ぜる際の注意

数字キーを作るかどうかは「ステージ内に選択式ルールが一つでもあるか」で開始時に決まります。問題ごとの切り替えではありません。現CSVに選択式と数字入力の混在ステージはありませんでしたが、今後混ぜるならこの部分も変更が必要です。

また、choiceColumn／multiSelectは問題種類より先に描画分岐されます（方眼はさらに先）。任意の問題種類と任意の回答方式を組み合わせても成立する汎用表示にはなっていません。

## 表示領域を決める際の結論

現在は「モンスター約20％」「数字キー約37％」が先に固定され、その間の約19％へ各問題が個別に置かれています。縦長の問題は約22％以上の範囲を使い、隣接する領域へ入り込んでいます。

通常の横式だけを基準に問題欄の高さを決めると、時計・筆算・分数・語群の追加で再び調整が必要になります。

次の設計では、問題文・図・回答欄を一つの問題表示として測り、上下の余白も含めて割り当てる必要があります。通常用の配置と、図や文章が大きい問題用の配置を用意し、方眼のようにモンスター部分も使う構成は明示的な別レイアウトとして扱うのが適切です。具体的な新比率は、この調査値を基準に見た目と操作領域の配分を決めてから設定します。
