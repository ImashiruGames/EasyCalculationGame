## 19-2のユーザー確認と対応

ログ全文を固定位置へ描いていたため、長いログが「とじる」へ重なっていた。本文の領域をx62・y274・幅266・高さ244に固定し、次の対応を追加した。

- 本文はTextのクロップで領域内だけに描画。見出しと閉じるボタンは固定。
- 本文上でマウスホイール、または上下のドラッグ・タッチでスクロール。全文を保持し、先頭から末尾まで読める。
- 続きがある時だけ操作案内とスクロール位置の目印を表示。
- 閉じる・再表示・Scene終了でポインター用イベントを解除。スクロール用の表示物はログと一緒に破棄。
- Phaser 4では従来のGeometryMaskがWebGLに対応していないため、WebGL/Canvas共通のTextクロップを使用。
- 確認ページ19-2の長文サンプルは、会話の最終ページまでのログを表示する。文字境界の表示には画面外へクロップされた部分も含まれるため、境界だけで表示崩れと判断しない。

型チェックを実施。ブラウザの自動操作・テストは行わず、スクロールと閉じる操作はユーザーによる確認待ち。

## 画面ごとに見る

[画面確認ページ](./screen-layout-preview.html?screen=02&debug=1) を開発サーバーで開く。上の選択欄で **36の画面・表示状態** を切り替える。既存の計算プレビューにも「ほかの画めんへ」を追加した。

- 番号は `screen-layout-review.md` の画面番号を継承。計算問題プレビューの問題番号とは別。
- 「サンプル」「長文のサンプル」「はじめから」を切り替えられる。長文は意図的な境界条件で、通常の保存内容を再現したものではない。
- 実際のSceneを390×844の論理座標で表示。ブラウザ上では縦横比を保って縮小する。以下の数値は縮小前のpx。
- 「文字のわくを見る」で文字の境界、「今の文字を見る」で現在の位置・大きさを調べられる。画面内でも、カードや他の文字と重なることはある。外にはみ出した文字の件数だけで正常とは判定しない。
- このページは起動時にStorageをページ内メモリーへ置き換えてからゲームを読み込む。通常のセーブを読み書きしない。切り替え・再読み込みでサンプルの変更は消える。開発サーバー専用で、配布用ビルドには追加しない。
- 確認ページ内の購入・報酬・編集はサンプルにだけ反映する。ひきつぎで出るコードもサンプル。

## 初回調査時の変更範囲と限界

- `npm run typecheck`：成功。
- `npm run build-nolog`：成功。通常の配布用エントリーをビルド。確認ページは開発用なので、このビルドの収録対象外。
- `git diff --check`：成功。自動テストスイートは実行していない。

- 追加したものは開発用の画面確認ページ・サンプル・調査メモ。製品Sceneの配置、保存形式、報酬、ゲームバランスは変更していない。
- 各項目は本物のSceneを使うが、報酬や詳細など一部は開発用アダプターから表示メソッドを呼ぶ。内部メソッド名が変わった場合は、この確認用定義も追従が必要。
- 自動の全画面巡回・端末網羅テストは行っていない。今回の実画面確認は02と14-1。ほかの項目はコード調査による候補としてユーザーが直接確認するために用意した。
- 青枠・赤枠はPhaserのText境界。DOM、画像、マスク、前面パネルによる遮蔽、文字の影まで含めた自動判定ではない。パネル背後のTextも一覧に含む。
- この一覧は現時点のデータと実装に基づく。今後は「文字の最大幅」だけでなく「折り返し後の最大高さ」と「入りきらない場合の扱い」を画面ごとに決める必要がある。
